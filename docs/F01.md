# F01: Authentication & Session Management

## 1. Feature Overview
- **Feature ID**: F01
- **Module Name**: `auth`
- **Backend Path**: `fortlio-be/src/modules/auth/`
- **Frontend Path**: `fortlio-ui/src/features/auth/`
- **Status**: In Progress (Backend ~85%, Frontend ~40%, Overall ~62%)

F01 covers user onboarding, registration, secure credential verification, JWT token lifecycle (access + refresh tokens), session storage via Redis, email verification via AWS SES, and logout functionality.

## 3. Backend Architecture (`fortlio-be/src/modules/auth/`)

### File Organization
```
fortlio-be/src/modules/auth/
├── auth.controller.ts    # Request handling & HTTP response formatting
├── auth.service.ts       # Business logic, password verification, token issuance
├── auth.route.ts         # Express router (/auth/*)
├── auth.validation.ts    # Zod schemas for register, login, verification
├── auth.interface.ts     # TypeScript interfaces for auth DTOs
├── auth.queries.ts       # MongoDB aggregation pipelines for user authentication lookup
├── auth.constants.ts     # Error and success messages
├── auth.registry.ts      # OpenAPI / Swagger registration
└── index.ts              # Barrel exports
```

### Endpoints
- `POST /auth/register`: Register new user (`fullName`, `email`, `password`, `role`: `'candidate' | 'hr'`).
- `POST /auth/login`: Authenticate credentials, return `accessToken`, `refreshToken`, user metadata.
- `GET /auth/refreshToken`: Exchange valid refresh token for a new access token.
- `GET /auth/logout`: Revoke active session in Redis.
- `GET /auth/verifyEmail?token=...`: Verify user email token.
- `POST /auth/resendVerification`: Resend email confirmation token.

### MongoDB Aggregation & Coding Rules
- Per project rules: Offload transformation to MongoDB aggregation.
- Login user lookup must aggregate role permissions, active session flags, and candidate/hr profile link in a single `$match` + `$lookup` + `$project` pipeline in `auth.queries.ts`.
- Mongoose is only used for basic `User.create()` and `User.updateOne()`.

## 5. Testing Specifications

### Bun Unit Tests (`fortlio-be/__tests__/auth.controller.test.ts`)
- `register`: Valid candidate payload creates user and returns 201.
- `register`: Duplicate email throws 409 Conflict.
- `login`: Correct email/password returns tokens and user object.
- `login`: Invalid password returns 401 Unauthorized.
- `verifyEmail`: Valid token activates user account.
- `logout`: Clears Redis session key.

### Playwright E2E Tests (`e2e/tests/auth.spec.ts`)
1. User navigates to `/register`, selects "Candidate", fills form, submits.
2. User sees verification pending screen.
3. User visits `/login`, submits valid credentials, redirected to `/candidate-profile` or `/create-profile`.
4. Invalid login displays Shadcn alert/toast error.
