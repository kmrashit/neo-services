# F07: Real-Time & Stored Chat Messaging

## 1. Feature Overview
- **Feature ID**: F07
- **Module Name**: `connection` (Chat Subsystem) & `core-clients/web-socket.client.ts`
- **Backend Path**: `fortlio-be/src/modules/connection/` & `fortlio-be/src/core/core-clients/web-socket.client.ts`
- **Frontend Path**: `fortlio-ui/src/features/chat/`
- **Status**: Completed (Backend 100%, Frontend 100%, E2E 100%, Overall 100%)

F07 enables real-time 1-on-1 direct messaging between connected candidates and HR recruiters. Messages are permanently stored in MongoDB, support unread status tracking, and are broadcast live via Bun WebSocket (`wsHandler`).

## 3. Backend Architecture (`fortlio-be/src/modules/connection/`)

### File Organization
```
fortlio-be/src/modules/connection/
├── connection.controller.ts    # sendMessage & getChatHistory methods
├── connection.service.ts       # Chat message persistence and history retrieval
├── connection.route.ts         # /chat/send and /chat/history/:connectionId
├── connection.validation.ts    # SendMessageValidation Zod schema
├── connection.queries.ts       # Chat history pagination pipeline
└── models/
    └── chat-message.model.ts   # ChatMessage schema (connectionId, senderId, message, readAt)

fortlio-be/src/core/core-clients/
└── web-socket.client.ts        # WebSocketHandler with JWT auth & room dispatch
```

### Endpoints & Sockets
- `POST /connections/chat/send`: Auth-guarded (`sendMessage`). Stores message in MongoDB and triggers real-time WS push to recipient room.
- `GET /connections/chat/history/:connectionId`: Auth-guarded (`getChatHistory`). Query: `page`, `limit`. Returns historical messages sorted ascending by creation date.
- `WebSocket ws://<host>:<port>`: Authenticates token on handshake, joins personal channel, receives live events (`CHAT_MESSAGE`, `MESSAGE_READ`).

### MongoDB Aggregation & Coding Rules
- In `connection.queries.ts`, use an aggregation pipeline for `getChatHistory`:
  - `$match`: connectionId and active state.
  - `$sort`: `{ createdAt: -1 }` for index efficiency, followed by reverse in pipeline or query projection.
  - `$project`: senderId, message, createdAt, readAt.
