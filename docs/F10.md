# F10: AI Interactive Interviews & Domain Readiness Evaluation

## 1. Feature Overview
- **Feature ID**: F10
- **Module Name**: `interview`
- **Backend Path**: `fortlio-be/src/modules/interview/`
- **Frontend Path**: `fortlio-ui/src/features/interview/`
- **Status**: Completed (Backend 100%, Frontend 100%, Testing 100%, Overall 100%)

F10 empowers candidates across any profession or specialty (software engineering, healthcare/medicine, law, finance, design, science, education, etc.) to practice and showcase their domain mastery through **AI-Powered Interactive Interviews**.

### Core Value Proposition:
1. **Adaptive Domain Simulations**:
   - Tailored to the candidate's chosen field and seniority (e.g. distributed systems failure modes for engineers, clinical triage hypotheticals for medical professionals, IP cross-licensing negotiations for lawyers, or portfolio design critique for UI/UX designers).
   - The AI interviewer poses initial scenarios, listens/reads the candidate's responses, and dynamically asks deep follow-up questions testing problem-solving structure, technical rigor, and edge-case handling.
2. **Multi-Modal Interaction**:
   - Voice audio (speech-to-text / text-to-speech) or text-based conversation modes.
3. **Comprehensive Readiness Scorecard**:
   - Produces quantitative and qualitative scores: **Domain Depth**, **Problem-Solving Rigor**, **Communication & Clarity**, and **Leadership & Composure**.
   - Generates actionable constructive feedback for candidate improvement.
4. **Recruiter Talent Verification**:
   - Candidates can opt-in to display their verified "AI Interview Readiness Badge" and summary report on their public portfolio, helping recruiters spot top candidates instantly.

## 3. Backend Architecture (`fortlio-be/src/modules/interview/`)

### File Organization
```
fortlio-be/src/modules/interview/
├── interview.controller.ts    # startSession, submitResponse, concludeSession, getReport
├── interview.service.ts       # LLM prompt orchestration, session state management
├── interview.prompts.ts       # Domain interview prompts tailored to taxonomy professions
├── interview.route.ts         # /interview/* Express router
├── interview.validation.ts    # Zod schemas for session initialization and response payloads
├── interview.queries.ts       # Aggregation pipelines for interview history and candidate badges
├── interview.constants.ts     # Rubrics, duration limits, scoring thresholds
├── interview.registry.ts      # OpenAPI specification
└── models/
    └── interview-session.model.ts # Mongoose schema for interview sessions
```

### Endpoints
- `POST /interview/start`:
  - Body: `{ interviewType: 'domain_technical' | 'behavioral_leadership' | 'case_study', specialty: string, targetLevel: string }`
  - Generates initial contextual question based on candidate background.
- `POST /interview/session/:id/respond`:
  - Body: `{ answerText: string, audioDurationSeconds?: number }`
  - Returns next question or follow-up prompt.
- `POST /interview/session/:id/conclude`:
  - Finalizes session, grades candidate answers against multi-dimensional rubric, and generates readiness score.
- `GET /interview/report/:id`:
  - Public/private access depending on candidate sharing settings.
