# F02: User Account & Role-Based Access Control (RBAC)

## 1. Feature Overview
- **Feature ID**: F02
- **Module Name**: `user` & `role`
- **Backend Path**: `fortlio-be/src/modules/user/` & `fortlio-be/src/modules/role/`
- **Frontend Path**: `fortlio-ui/src/features/user/`
- **Status**: Completed (Backend 100%, Frontend 100%, Overall 100%)

F02 manages core user identities, profile accounts, role definitions (`candidate`, `hr`, `admin`), privilege assignments, Redis privilege caching, and the video ad consumption counter (`/user/watch-ad`) used for platform monetization.

## 3. Backend Architecture

### File Organization
```
fortlio-be/src/modules/
├── user/
│   ├── user.controller.ts    # User CRUD & watchAd handler
│   ├── user.service.ts       # Database operations for users
│   ├── user.route.ts         # /user/* router
│   ├── user.validation.ts    # Zod schemas for user mutations
│   ├── user.queries.ts       # MongoDB aggregation pipelines
│   ├── user.constants.ts     # User status messages
│   └── models/
│       └── user.model.ts     # User Mongoose schema (email, password, role, coins)
└── role/
    ├── role.controller.ts    # Role & privilege endpoints
    ├── role.service.ts       # Role RBAC service
    ├── role.route.ts         # /role/* router
    ├── role.validation.ts    # Zod schemas for role management
    ├── role.queries.ts       # Role MongoDB aggregation pipelines
    └── models/
        ├── role.model.ts      # Role schema (name, privileges)
        └── privilege.model.ts # Privilege schema (code, name, tag)
```

### Endpoints
- `GET /user/getUsers`: Paginated list of users (cached).
- `GET /user/getUserById`: Fetch current user details.
- `POST /user/createUser`: Create user account.
- `PUT /user/updateUserById`: Update user profile data.
- `DELETE /user/deleteUserById/:userId`: Soft/hard delete user.
- `POST /user/watch-ad`: Increments search coins by verifying SHA256 checksum token.
- `GET /role/getRoles`: Fetch all available system roles (cached).
- `GET /role/getRolesWithPrivileges`: Fetch full permission matrix.

### MongoDB Aggregation & Coding Rules
- Use `user.queries.ts` aggregation pipelines (`$match`, `$lookup` to role and candidate profile, `$project` sanitized fields) rather than JS-level object mutations.
- `watch-ad` updates coin count via atomic `$inc: { coins: 1 }` or `$set`.
