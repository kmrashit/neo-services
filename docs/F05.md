# F05: HR Candidate Search Engine & Monetization (Ad Gate)

## 1. Feature Overview
- **Feature ID**: F05
- **Module Name**: `hr`
- **Backend Path**: `fortlio-be/src/modules/hr/`
- **Frontend Path**: `fortlio-ui/src/features/hr/`
- **Status**: In Progress (Backend ~85%, Frontend ~15%, Overall ~50%)

F05 is Fortlio's recruiter discovery engine and monetization core. HRs search candidates across all professions and disciplines using keyword filters (profession, skills, industry, experience, education, location) backed by Typesense. Monetization is strictly enforced: every 2 searches deplete the user's search coins, requiring the user to watch a sponsored video ad (`/user/watch-ad`) to replenish search quota.

## 3. Backend Architecture (`fortlio-be/src/modules/hr/`)

### File Organization
```
fortlio-be/src/modules/hr/
├── hr.controller.ts          # Search, profile upsert, history endpoints
├── hr.service.ts             # Typesense search query builder & profile service
├── history.service.ts        # SearchHistory & ProfileView logging service
├── hr.route.ts               # /hr/* router with Checksum & AuthGuard
├── hr.validation.ts          # Zod validation schemas
├── hr.interface.ts           # Types & interfaces for HR operations
├── hr.queries.ts             # MongoDB aggregation pipelines for history
├── hr.constants.ts           # Status and monetization messages
├── hr.registry.ts            # OpenAPI registry
└── models/
    ├── hr.model.ts               # Recruiter company profile schema
    ├── search-history.model.ts   # Logged search queries per HR
    └── profile-view.model.ts     # Logged candidate profile views per HR
```

### Endpoints
- `POST /hr/profile`: Auth-guarded (`upsertHrProfile`). Saves recruiter details (company, designation, company website).
- `GET /hr/profile/:userId`: Auth-guarded (`getHrProfile`). Returns recruiter profile.
- `GET /hr/search`: Auth-guarded (`searchCandidates`) + `ChecksumVerifyMiddleware`.
  - Checks if user has available search coins (`user.coins > 0`).
  - If coins <= 0, rejects with 403 / Payment Required asking to watch an ad.
  - Decrements coins, queries Typesense candidate index (`sensiSearch`), logs query into `SearchHistory`.
  - Returns sanitized candidate cards (phone/email masked unless connected).
- `GET /hr/history/searches`: Auth-guarded (`getSearches`). Returns previous search keywords and timestamps.
- `GET /hr/history/viewed-profiles`: Auth-guarded (`getViewedProfiles`). Returns list of viewed candidates.

### MongoDB Aggregation & Coding Rules
- History retrieval in `hr.queries.ts` uses MongoDB aggregations with `$lookup` to `candidate_profiles` to fetch preview cards for viewed candidates in a single round-trip.
- Typesense syncing is handled by BullMQ worker in `core/core-workers/bullmq.workers.ts` (`initializeBullMQCandidatesTypesenseSync`).

## 5. Testing Specifications

### Bun Unit Tests (`fortlio-be/__tests__/hr.controller.test.ts`)
- `upsertProfile`: Successfully saves valid recruiter profile.
- `upsertProfile`: Throws 400 when email is invalid.
- `getProfile`: Returns full recruiter details.
- `searchCandidates`: Deducts search coins and queries candidate collection.
- `searchCandidates`: Throws 403 when search coins are exhausted.
- `getSearches` & `getViewedProfiles`: Returns user search history records.

### Playwright E2E Tests (`e2e/tests/hr-search.spec.ts`)
1. Recruiter logs in, enters "React Senior" in Search Bar.
2. Search executes; remaining searches count decrements from 2 to 1.
3. Second search executes; count reaches 0.
4. Third search triggers Video Ad Modal; user watches simulation, clicks "Claim Search Coins".
5. Search unlocks and returns candidate cards.
