# F11: Job Board & Recruitment Engine (HR Job Postings ↔ Candidate AI Job Suggestions)

## 1. Feature Overview
- **Feature ID**: F11
- **Module Name**: `job` (Backend `fortlio-be/src/modules/job/` & Frontend `fortlio-ui/src/features/jobs/`)
- **Backend Path**: `fortlio-be/src/modules/job/`
- **Frontend Path**: `fortlio-ui/src/features/jobs/`
- **Status**: Specified / In Progress

F11 establishes the dual-sided job marketplace connecting Recruiters/HRs and Candidates based on authentic credentials, verified domain skills, and Forti learning velocity:

### 1. HR / Recruiter Workflow:
- **Job Postings Management (`/hr/jobs`)**:
  - Recruiters create, publish, edit, and archive job postings across all professions (Engineering, Healthcare, Design, Law, Finance, Science, Marketing, etc.).
  - Fields: `title`, `companyName`, `profession`, `department`, `location`, `workplaceType` (`remote` | `hybrid` | `onsite`), `experienceRequired` (years), `skillsRequired` (array), `salaryRange`, `description` (Markdown), `status` (`active` | `closed` | `draft`).
  - **Applicant Tracking**: View candidates who applied, inspect their verified portfolio, Forti velocity score, and initiation connection/chat.

### 2. Candidate Workflow:
- **AI Job Suggestions & Smart Search (`/jobs`)**:
  - **AI Job Suggestions**: Candidates receive personalized job recommendations dynamically scored and ranked against their verified profile skills, profession, and Forti learning velocity score.
  - **Keyword & Faceted Search**: Filter jobs by profession, required experience, remote/hybrid status, and domain tags.
  - **One-Click Application & Recruiter Connect**: Candidate submits profile and markdown resume with optional cover note directly to the hiring recruiter.

## 3. Backend Architecture (`fortlio-be/src/modules/job/`)

### File Organization
```
fortlio-be/src/modules/job/
├── job.controller.ts          # createJob, getJobs, getSuggestions, applyJob, getApplicants
├── job.service.ts             # Persistence and scoring algorithms
├── job.route.ts               # /job/* endpoints with AuthGuard
├── job.validation.ts          # Zod validation schemas
├── job.interface.ts           # Types & interfaces for Job and Application
├── job.queries.ts             # MongoDB aggregation pipelines for job matching
├── job.constants.ts           # Status and error constants
└── models/
    ├── job.model.ts           # Job postings collection
    └── job-application.model.ts # Job applications collection
```

### Endpoints
- `POST /job/create`: HR-guarded. Creates a new job posting.
- `GET /job/hr/my-posts`: HR-guarded. Returns job postings created by this recruiter with applicant counts.
- `PUT /job/:jobId`: HR-guarded. Updates job details or changes status to `closed`.
- `GET /job/search`: Candidate/Public. Filter jobs by keyword, profession, experience, workplace type.
- `GET /job/suggestions`: Candidate-guarded. Computes AI job matching percentage based on candidate's skills array and experience.
- `POST /job/apply/:jobId`: Candidate-guarded. Submits application for review.
- `GET /job/:jobId/applicants`: HR-guarded. Returns applicants for a specific job posting.

## 5. Testing Specifications
- **Bun Unit Tests (`job.controller.test.ts`)**:
  - `createJob`: Succeeds with valid HR parameters.
  - `createJob`: Rejects if non-HR tries to post a job.
  - `getSuggestions`: Returns jobs with computed match score based on candidate skills.
  - `applyJob`: Prevents duplicate applications for the same job.
- **Playwright E2E Tests (`e2e/tests/jobs.spec.ts`)**:
  - HR recruiter creates and publishes a job post.
  - Candidate logs in, views `/jobs`, verifies job appears under AI suggestions with match score.
  - Candidate clicks "Quick Apply", verifies submission confirmation.
  - Recruiter logs in and verifies applicant appears in applicants drawer.
